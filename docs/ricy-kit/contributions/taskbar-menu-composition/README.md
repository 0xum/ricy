# App options in docked Noctalia panel

The right button on a taskbar icon now uses a native Panel, registered as `ricy:taskbar-menu`, with the same PanelManager from the tray drawer. The panel opens next to the icon and the bar that received the click on the corresponding monitor. It inherits the bottom/opacity of the bar, junction drawing, animation, blur and native external closure. In the Ricy configuration this results in background 0,70 and continuity with the taskbar by ricyblur. It does not change internal menus of applications or context menus of the tray items.

The options continue to be generated by the original code: Pin/Unpin when there is desktop entry, actions of this entry, Close and Close All when applicable. Closing and fixing actions keep their original handlers; callbacks use the widget lifeguard and activation is postponed until the entry event is finished.

The width is calculated by the widest text, with minimum content 240 px on scale 1, and native panel padding. Height uses all inputs, separators and padding; **there is no ScrollView or limit of 12 lines**. PanelManager already discountes padding: implementation does not apply it a second time in content. Arrows navigate and Enter/Space activate; Escape/click external follow the native flow of the panel. Size is still subject to monitor/compositor boundaries; very extensive lists have not been tested.

## Reproduce

Compatible with Noctalia 5.2.1, commit `6ef43e2bf2f3d5b4205ec72a72e34a2ab76ce3b4`. Prepare permanent integration. This patch **compound** also includes previous notification fixes and Home wallpaper, preserving the full state of the local variant.

```bash
cd "$HOME/ricy-kit/contributions/taskbar-menu-composition"
bash build.sh
python ../notification-continuity/enable.py
```

Dependencies: the contribution notification-continuity and BUILDING.md upstream. The script fixes version/commit and accepts only a clean source or the same compound patch already applied. In the cache of a previous variant, the script refuses differences; preserve the previous folder before starting a new cache:

```bash
# Run only when the cache still contains the known previous variant.
# Use a backup name that does not yet exist; do not overwrite personal source.
mv "$HOME/.cache/ricy-noctalia-src-5.2.1" "$HOME/.cache/ricy-noctalia-src-5.2.1-anterior"
bash build.sh
```

With defined XDG_CACHE_HOME, adjust both paths. The local installation continues made by the existing activator, with temporary binary/drop-in backup and KillMode to preserve applications. `/usr/bin/noctalia` and package assets remain installed normally. The old notification-continuity compiler corresponds to the previous variant and does not accept this compound cache; use the compiler of this contribution to the current state. Review/recompile while updating Noctalia. Shared Blur continues depending on the blur-continuity contribution to the corresponding KWin version.

## Validate and restore

Right click on applications in the bar of each monitor; check out applicable options, full list without scrolling, Escape/external click and actions in a disposable application. Do not close applications with work to test. In this implementation: final compilation and profile validation passed; shell and active adapter, KillMode normal reset, ricyblur loaded. The user saw the native panel in the first version and pointed scrolling; corrected the duplicate padding, removed ScrollView and applied the final variant. The final visual validation and execution of each action by the user has not yet been registered.

To return to the previous version, use the backup printed on the activation:

```bash
python ../notification-continuity/enable.py --restaurar "$HOME/.local/state/ricy-notificacoes-backups/DATA-HORA"
```

The backup of the first change of this contribution goes back to the previous popup menu; the second turn to the first composition, which still featured scrolling. Language configuration, climate and other preferences are binary independent. To compile the old version again, preserve the compound cache and use clean font with the corresponding compiler/patch. Do not reuse a cache with different changes without reviewing your diff.
